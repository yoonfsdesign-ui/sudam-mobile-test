## 3. 화면 시연 시 테스트할 기능

- 390px 모바일에서 화면 좌우 스크롤이 생기지 않는지
- PC에서 사이트 너비가 원본처럼 최대 480px로 제한되는지
- 헤더 메뉴, 햄버거, 푸터, 140px 스크롤 후 예약 고정 바가 유지되는지
- 모임 허브의 7개 카드를 누르면 각각 다른 상세 URL로 이동하는지
- 모임 상세 페이지의 코스 링크·관련 후기 링크·상담 요청 버튼이 이어지는지
- 모임 상세 ‘예상 식사 예산 계산’에 인원을 입력하면 단순 합산 금액이 바뀌는지
- 후기에서 인원+코스+모임+복수 태그 필터를 함께 선택하고 초기화할 수 있는지
- 필터 결과가 없으면 빈 상태 안내가 표시되는지
- 후기 카드 → 상세 → 모임·코스·예약 링크가 연결되는지
- 예약 상담폼 필수 입력 검사, URL을 통한 모임 유형 미리 선택, 메일 초안 열기, 내용 복사 기능
- 지도(네이버/카카오), 주소 복사, 주차 안내, FAQ 펼침
- 초대장 스타일 3개, 입력 즉시 미리보기, 1080x1440 PNG 생성, 링크 복사 및 링크로 입력내용 불러오기

## 4. 실제 운영 전에 반드시 연결 또는 확인할 항목

**시연용 콘텐츠**

- `reviews/`에 표시된 모든 후기는 **실제 이용 후기가 아닌 테스트 데이터**입니다. 고객명, 방문일, 검증되지 않은 별점은 넣지 않았습니다. 실제 후기를 게시하려면 데이터 제공 방법/API/관리자 등록 절차가 필요합니다.
- 모임 7종 상세페이지의 일부 행사 서비스·옵션은 **상담 시 확인할 항목**일 뿐 실제 제공 서비스 확정이 아닙니다. 특히 돌상, 웨딩, 행사 장비 등은 반드시 운영팀 확인이 필요합니다.
- 사진은 v4.3 기존 이미지 폴더의 테스트 이미지를 재사용했습니다. 화면은 그럴듯해 보여도 실제 공간/행사 사진이 아닌 경우가 있습니다.
- `진연상 62,000원`, `수라상 82,000원`은 **기존 메인 가안에 노출된 표시 가격을 가져온 것**입니다. 공식 메뉴 확정 전에는 운영 가격으로 간주하지 마세요. 대감상은 가격 미확정 상태입니다.
- 기업 고객사 로고, 인증/블루리본의 구체적 수상 연도, 룸 수용 인원, 메뉴 구성, PDF 제안서 및 메뉴판도 실제 자료 교체가 필요합니다.

**서버 연동이 필요한 기능**

- **실제 후기 실시간 동기화**: 외부 리뷰 시스템/API 또는 관리자 CMS 필요. 현재는 브라우저에서 시연 데이터 필터만 처리합니다.
- **상담폼 접수**: GitHub Pages에는 백엔드가 없습니다. 현재 요청서를 작성해 `mailto:koreasudam@naver.com`으로 **사용자 이메일 프로그램의 초안을 여는 방식**입니다. 자동 전송이나 예약 확정은 하지 않습니다. 서버에 정보를 저장하지 않습니다.
- **예약 링크**: `js/site-config.js`에서 `reservation`, `kakao`, `wechat`에 실제 URL을 등록해 주세요. 현재 빈 링크를 누르면 '연결 URL 준비 중' 메시지가 나옵니다.
- **PDF 다운로드**: `js/site-config.js`에서 `menu_pdf`, `proposal_pdf`를 실제 PDF 주소로 설정해야 작동합니다.
- **SNS/그룹 링크, 개인정보 방침 페이지**도 `js/site-config.js`에서 확인·연결해야 합니다.

초대장 링크는 제목·문구·날짜 등의 값을 **URL 쿼리 파라미터**로 넣어 공유합니다. 서버 저장 없이 작동하지만, 링크가 외부에 공유될 수 있으므로 개인 연락처나 민감한 정보는 입력하지 않도록 안내합니다.
